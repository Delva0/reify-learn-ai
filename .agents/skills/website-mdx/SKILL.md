# 技术内容写法

## 读者与内容取舍

- 面向已有丰富后端工程和深度学习经验的读者，使用领域术语，不补讲其已掌握的基础。
- 解释不清时，不默认追加内容。先通过删减无关信息、重复解释和过早引入的细节显露主线与关系；只有缺失的前提确实阻碍理解时才补充。取舍以能否帮助理解为准，不以信息量为目标。
- 源码本身是文章内容的一部分。用内部文件链接直接呈现类型、配置、调用和分支；正文集中解释跨文件关系、隐含前提、生命周期约束及实现与表象的差异，不逐行转述读者点开即可读懂的代码。
- 不得生造概念。沿用源码、配置、API 或官方文档已有名称；解释组合关系用普通句子，不为资源组合另起正式术语。
- 代码标识用于定位实现，解释要落实到对象关系、实际行为及其原因。
- 按任务目的区分机制讲解与操作教程，避免在两种叙述之间无意切换。
- 标题正式、直接，不用冒号式标题；简单行为融入段落，复杂机制才单独设标题。正文不混入作者工作过程或对文章自身的重复说明。

## 机制与叙述

- 开篇明确本仓负责什么、产出什么、由谁加载或调用，以及上下游边界；不能让读者靠后文或追问补齐这些前提。
- 对象首次出现时明确所属组件与职责。涉及跨组件配置时，交代定义者、承载位置、解析者及行为影响。
- 按源码实际顺序连接调用、数据流、状态转换与结果。明确调用者和被调用者，区分网络请求、同进程函数调用与设备执行，不靠孤立 API 清单解释机制。
- 创建、共享、复用和并发要落实为对象数量、所有者、创建时点、使用方式与销毁条件。数量由配置决定时明确前提，不含糊泛化或擅自定值。
- 区分平台提供的机制、当前仓库的实现与示例取值，明确各自的适用前提；核对引用内容与讲解改写的界限。
- 分支说明判断与行为差异。正文保留影响整体流程的结论，具体判断和状态转换优先在对应源码处说明。
- 选择信息密度高、可核对的表达形式，以具体输入、结构、代码和量化结果支撑解释，避免用文字转述替代直接呈现。
- 用契约、所有权、生命周期和不变量推导设计，以读者能重建核心实现为目标；解释所需的项目背景在首次使用处交代。

## 正文与 note

- 正文、note 与链接的源码共同构成完整内容。重新组织时保留机制所需的具体事实、条件与推导；源码能直接承接的信息无需反复转述，跨文件才能得出的理解不能只用链接替代。
- 对照代码讲解时，优先采用 inline code viewer 的“就地注释”风格：将局部释义、隐含前提与行为差异附在对应标识符、表达式或语句上，将后续源码入口放在相关调用处。正文串起整体机制与跨文件关系，保留连续叙述。
- 按读者当前的问题选择代码范围与跳转落点，让源码、说明和后续调用就近可读；需要对照时使用语义染色或多面板。控制注释密度，集中补充代码本身不易直接呈现的理解。
- note 放在相应信息首次需要的位置，解释应具备足够的局部上下文。
- 同处只表达一次：不在 note 中重复正文、整段命令或另一条 note。只需跳到代码或来源时使用普通链接。

## 数学、代码与来源

- 可形式化的关系优先用数学，明确业务含义、适用条件和不变量；区分源码事实、数学性质与实现判断。
- 公式染色服务于语义对照：少量主题适配的强调色、同义同色、中性运算骨架。
- 摘取能说明机制的调用、签名、结构和分支，保留语言标识与语法高亮。示例提供理解实现所需的具体输入和取值前提。
- 源码入口放在需要它的句子中，选中足以理解当前问题的完整代码范围；跨函数的理解可在同一链接选中多段。避免把关键依据堆到段末导航清单，让读者自行猜测对应关系。
- 仅在摘录、改写或对照能直接揭示机制时重复展示代码；已有原始配置、请求或示例可直接阅读时，优先链接。公式与图示用于表达源码没有直接呈现的关系、不变量或量化结果。
- 注释不改变原代码、公式的结构与渲染；文件组织用嵌入组件呈现，图示和交互直接解释数据、数学或代码。
- 公式片段用 `\annotate{标识}{TeX 片段}` 标注，说明集中定义于 `Annotations.notes`；保留 KaTeX 排版与语义染色。
- 内嵌代码与文件源码共用 `CodeBlock` 的结构化标注，不改写代码或高亮结果。

## MDX 与链接

- 知识库按仓库与知识主题组织，H1 直接命名独立主题，不添加序号；页面之间通过概念与实现依赖的 wiki 链接关联。
- 每页是一份可独立阅读的技术报告兼学习资料，围绕自身主题讲清问题、机制、关键约束与源码依据；理解所需的前提在本页交代，不假定读者按某个页面次序阅读。
- 分页以完整的技术问题或机制为边界。同一条数据流、调用链或生命周期优先在同页用 H2–H6 组织；只有主题能独立成篇且拆分有助检索与理解时才新增 H1，不为单个概念、API 或简短说明单独分页。
- 一个仓库版本保留一份 MDX；每个 H1 划分一个主题页，其内容延续到下一个 H1。
- H2–H6 是当前逻辑页内的章节，不为分页升级标题；目录忠实保留整份 MDX 的标题文本与层级。
- H1–H6 自动生成原生标题链接，无需手写锚点链接或拆分物理文件；跨页内容使用生成的页面链接。
- 同份 MDX 内的章节引用使用标题或段落锚点，由渲染器转换跨 H1 的页面路径，不手算分页序号。
- 依赖文章沿用同一讲解方式，以普通 wiki 链接连接。
- 导航与来源使用 link，文字直接命名目标；源码定位到对应版本和实现。
- 局部释义使用 note；同时需要释义与跳转时才用 linked note。
- note 附于被解释的原文，不使用 numbered note。
- 交叠范围在 MDX 中手工拆开，不交给组件推断；同处信息不重复放置。
- 元信息留在页面元信息区，正文只保留理解当前设计所需的内容。

## CodeBlock 与代码查看链接

- 在 MDX 中预定义具名 `CodeBlock`，链接只写 `?fp=code&block=名称`；正文、note 内跳转和跨代码调用都复用该定义，不把标注塞进 URL。
- `id` 在整份仓库版本 MDX 中唯一，命名体现代码用途；跨 H1 分页仍可引用。跨文章引用在 `?` 前加目标文章路径。
- 内容来源二选一：`code={字符串}` 或 `src="文件路径或 HTTP(S) URL"`。相对路径属于当前仓库版本；跨仓库源码固定 commit。
- `render={false}` 只隐藏正文代码块，不影响定位、标注、缓存或 viewer；省略时正常渲染。隐藏与内容来源独立。
- `.md`、`.mdx` 资源默认按文章渲染，内嵌文档用 `language="markdown"` 或 `language="mdx"` 声明；保留真实标题层级，viewer 内按 H1 分页，源码切换不需要作者另备一份内容。
- `lines="10-20,30,40-50"` 定义多段导航与整行强调；从 1 开始，两端包含。每段可附 `@blue` 或 `@amber`，默认灰色，不改语法前景色。
- `notes={[{at,desc}]}`、`links={[{at,href}]}`、`marks={[{at,color}]}` 分别表达说明、跳转与强调；使用 JSON 数据，不写自定义标记字符串。
- `at={{line:10,text:"value",occurrence:2}}` 定位指定行的子串；省略 line 时在全文定位，省略 occurrence 时取首次。只有 line 时选整行。
- 正则定位使用 `at={{line:10,pattern:"value\\d+",flags:"i"}}`；跨行范围使用 `at={{from:{line:10,text:"start"},to:{line:12,text:"end"}}}`，包含两端匹配。
- `notes={{"原文子串":"说明"}}` 是全文首次匹配的简写。重复内容使用精确定位，范围不得为空或越界。
- 同一范围的 note、link、mark 可组合；note 与 link 同处即 linked note。部分交叠在内容中显式拆开，不交给组件推断。
- link 的 href 可继续引用另一个 block；一个定义可被多处、多面板复用，不递归编码完整配置。
- 多面板使用 `?fp=!((type:code,block:a),(type:code,block:b))`；单面板保持平铺 query，non-modal viewer 不进入链接。
- `?fp=code&file=资源&lines=范围` 保留给临时文件浏览，file 接受相对路径或 HTTP(S) URL，查看器也可展示图片。普通 HTTPS link 保留网页跳转。
- 同一 src 共用资源与高亮缓存；构建时校验标注并缓存文件，预取包含 block 内继续链接的源码依赖。
